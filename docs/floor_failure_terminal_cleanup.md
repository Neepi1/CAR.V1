# 切图失败应终止任务，而不是锁住其他功能

## 纠正范围

之前的 `floor_failure_asset_admission.md` 只放行失败后的离线配置编辑，
没有解决切图事务、定位桥和乘梯清理仍保留失败锁的问题。本次修改失败退出
链路，不改变地图资产、Nav2 算法、速度、雷达或碰撞配置。

## 失败退出契约

1. 切图失败仍返回失败，保留最初的失败原因，不将清理误报为切图成功。
2. 区分“目标请求曾经发出”和“目标请求现在仍未结束”。完成过加载地图，
   后续掩码失败，不应因此永久保留切图的停车和定位暂停。
3. 桥接 ABORT 结束该事务，保持真实 `runtime_context_valid=false`，
   不凭空恢复旧图或声称新图定位成功。已终结事务不能用迟到或更高序号的
   BEGIN/COMMIT 重新接管，也不能用旧 ABORT 干扰新事务。
4. 清理完成和定位有效是两个独立事实。确认请求结束、终止桥接事务、持久化
   失败上下文并释放本事务资源后，任务结束为 FAILED；定位未就绪本身不再
   把终态改写为 FAILED_LOCKED。
5. 真正未结束的旧写入仍必须先处理，不能杀掉客户端或删除 future 后假定
   服务器不会再改图。该冲突属于旧请求与新切图，不是无限期的历史失败锁。
6. API 使用当前证据：正在切图仍互斥；历史 FAILED 不再锁存。重新选图、
   启动链路、建图和定位恢复不要求旧图先定位成功。导航目标、读取当前位姿
   等依赖地图定位的功能，仍必须满足当前真实定位条件。
7. 乘梯非持久恢复策略下，清理本次资源不再等待“地图已可导航”；已有动作
   终态、双里程计静止、未决副作用、资源归属及条件停车释放检查保留。

## 验证边界

本次先在隔离环境复现，再修复；不能以“API 能编辑点位”替代上述验证。

- 事务 core/executor：失败且已释放资源、定位无效，仍应正常 FAILED；
  不发布成功地图身份，不伪造定位有效。26 项回归通过。
- 定位桥：ABORT 后新事务可开始，旧事务不能复活或干扰新事务；
  无效地图不能 force-accept；已运行隔离 ROS 服务测试。
- API：旧失败记录不得压过后续当前健康证据；无效定位不得阻止恢复入口；
  当前活动切图优先互斥。25 项回归通过，正式候选真实 HTTP 隔离测试通过。
- 乘梯清理策略：非持久模式不再调用定位 ready 前置探针；持久兼容策略仍
  执行严格探针，且新分支不伪造任何资源或停车证明。56 项策略测试通过。
- 实际 FloorSwitch Action 的“地图加载已结束、掩码失败、资源释放、再次
  切图”以及迟到请求场景已通过隔离 ROS 服务验证，结果见任务报告。

冷启动交接和嵌套服务超时不会被无条件当作已结束：已确认 adoption 且未触发
目标初始化，或收到精确目标 `runtime_ready` ACK，才证明启动侧无未决写入。
Isaac 已发出但结果未知、桥接 arm 超时等仍属于实际未决副作用；当前实现不会
自动猜测它们已取消。不能把普通热切图回归通过表述成这些场景也能立即解锁。

此文描述工作区修复契约，不代表生产二进制已更新。部署指纹和真实硬件验收
须单独记录；测试不发送真实车辆运动或真实楼层切换。

三个包的 Release 候选已编译，指纹及测试波动如实记录在
[`reports/floor_failure_terminal/README.md`](../reports/floor_failure_terminal/README.md)。
实际 Action 最终两项及各自单独复跑通过；一次隔离 rclcpp executor 异常日志
保留，未修改生产 ROS 库来绕过该异常。工作区修复与车端部署状态必须区分。
