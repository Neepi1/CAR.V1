## 恢复契约

- 导航明确被拒绝、ABORTED，或本地超时后原目标已明确终止：保留当前
  effect、原目标和首次选择的控制配置，在原有 hold/停稳/模式检查后重试。
  每次尝试使用不同的控制器 session；不会从呼梯、按键或前序点位重来。
- Action 接收/结果未知、取消、适配器故障、停稳/资源证据失败不被当作
  “可以再发一个目标”。用户取消优先；异常不伪装为远端成功。
- 切图明确暂态失败：等待原请求清理完毕，然后重切同一冻结目标地图。
  外部乘梯事务不变，内部切图尝试使用 SHA256(外部事务)+已存在的持久序号，
  避免复用定位桥已经终止的事务 ID。资源归属观察兼容旧 ID 与新命名域；
  不越权释放 floor manager 的资源。
- 清理完成是一次性事件，按当前尝试保存；hold/pause 缺失仍要求当前证据。
  旧目标未终止、仍有延迟请求或原资源未释放时，不叠加新切图。
- 切图 Action 已精确提交成功后，地图就绪/新鲜稳定位姿暂时未证明，只重验；
  不重复切图、不再请求 Isaac。异常和明确身份错误保留失败原因。
- caller pause 释放与 floor 完成竞态时，核对同一 Goal 的最终结果；
  不因观察时 floor pause 已正常释放而重复切图。

失败之间采用可被取消和现有适配器故障打断的 1 秒间隔，不限定暂态失败
尝试次数。成功路径不增加等待。原每次 Action / 服务超时、停稳要求、
位姿阈值和用户取消收尾不变。不会沿用失败周期的运动指令。

切图自动重试只允许协议中的 11、30–34、40 暂态失败码。
非法目标、资产缺失/损坏/不匹配、禁用 live switch、未知内部异常不无限重发。
本适配器超时取消后的明确 CANCELED 只处理既有 90/34 终态；操作员取消不重试。
该修复不是“任何硬件、地图或未知错误都能保证成功”。

## 审核修正（2026-09-22，取代 v3 可部署判断）

v3 的测试记录真实，但漏掉了成功/超时竞态和实际服务端版本依赖，不能直接部署。

- 导航超时收尾后读取**原 Goal 的同一个结果 future**，与正常完成共用最终判断。
  `SUCCEEDED` 不重发；用户取消优先；终态未知不重试；真正超时取消或 ABORTED
  保持既有恢复。已经取得的 hold/双里程计停稳证据复用，不重复等待。
- FloorManager 配套现有自动失败清理，保留超时的原始请求，原请求结束后再
  终结 bridge 事务并释放自己的资源。清理完成不要求地图定位重新 ready，
  也不等于目标地图成功。API 不直接清除 FloorManager 的 hold/pause。
- 从真实 `LoadMap` 返回点区分服务不可用（34）、响应超时（33）、非法地图
  （22）、其他未知错误（99）；保留原始原因和服务端 result。没有放行全部99。
- 实机定位桥旧 `ABORT` 会保留失败锁。配套候选采用已隔离验证的事务终结源码：
  只结束原事务，保持定位无效，允许新的精确事务 BEGIN，禁止旧事务再 BEGIN/
  COMMIT/ABORT 干扰替代事务。原目标 COMMIT 条件和定位算法不变。
- 启动 owner 原 `adopted` / `runtime_ready` 回执不证明退出清理结束。新增可选
  `cleanup_completed` / `effects_settled` / `owner_available` 终结回执，只在
  原退出清理返回后写入并匹配原 nonce/地图身份。旧回执缺字段意味着未知。
- `STARTUP_OWNER_EXITED; ` 是同次尝试的终结事件，不是需要不断刷新的心跳。
  API 保存该事件并明确结束恢复等待，保留原错误；不假装清理完成、不再发目标。
